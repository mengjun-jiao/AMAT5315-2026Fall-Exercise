# Week 7: Diffusion and Flow Matching

## Project Overview

This project studies diffusion models, deterministic sampling, flow matching,
and image completion. Each part is implemented and verified separately
according to the Week 7 learning sheet.

## Environment Setup

The project uses an isolated `uv` environment with the same dependency
management style as Week 6. Run commands from this directory:

```bash
uv sync
uv run python -c "import jax; print(jax.devices())"
```

JAX is expected to run on the CPU by default. The device check should report a
`CpuDevice`. All future commands should use `uv run` so that the lock file and
environment are used consistently.

## Directory Structure

- `scripts/` contains source code, experiment entry points, validation scripts,
  and plotting scripts.
- `evidence/` contains reviewable figures generated by verified commands.
- `artifacts/` contains formal numerical results and experiment settings.
- `inputs/` contains downloaded datasets and model files and is excluded from
  version control.

## Part 1: Diffusion Models on a Gaussian Mixture

The target distribution and the 1000-step forward diffusion are implemented in
`scripts/diffusion.py`. The independent verification script samples the four
Gaussian components, checks the noise schedule, compares the direct and
stepwise formulas, and reports the `t=1000` statistics:

```bash
uv run python scripts/verify_forward_diffusion.py
```

The numerical settings and verification output are saved to
`artifacts/part1_forward_diffusion.json`. No reverse process or learned
predictor is included in this subtask.

The full forward trajectory of the same 2,000 target samples can be rendered
with:

```bash
uv run python scripts/animate_forward_diffusion.py
```

This writes `evidence/part1_forward_diffusion.gif`,
`evidence/part1_forward_diffusion_stages.png`, and
`artifacts/part1_forward_diffusion_animation.json`. The animation uses fixed
coordinate limits for every frame and includes 201 frames from `t=0` through
`t=1000`; the six required stages are included in the static comparison.
With seed 7201, the generated `t=1000` sample has mean and variance recorded
in the JSON output for comparison with the standard Gaussian target.

The time-conditioned noise predictor uses the fixed configuration in
`diffusion.toml`: three 128-unit SiLU hidden layers, 32 sinusoidal time
features, float32 arithmetic, Adam, cosine learning-rate decay, batch size
512, and 25,000 updates. Train it with:

```bash
uv run python scripts/train_diffusion.py
```

Training records are saved to `artifacts/part1_diffusion_training.json`.
Checkpoint parameters are written locally to the ignored directory
`artifacts/checkpoints/` at updates 0, 50, 100, 200, 500, 1000, 2000, 5000,
10000, and 25000.

After training, run the 1000-step DDPM smoke test with:

```bash
uv run python scripts/smoke_test_ddpm.py
```

The smoke-test results are saved to `artifacts/part1_ddpm_smoke_test.json`,
with a small preview at `evidence/part1_ddpm_smoke_test.png`. This confirms
finite outputs for the initialization and final checkpoints. Checkpoint
animation and the quantitative final-distribution evaluation using 2,000
samples are provided by the following verification commands:

```bash
uv run python scripts/animate_diffusion_training.py
uv run python scripts/evaluate_ddpm_distribution.py
```

The checkpoint animation uses the same 10 initial Gaussian points and the same
1000-step reverse noise sequence for every checkpoint. It writes
`evidence/part1_diffusion_training.gif`,
`evidence/part1_diffusion_training_stages.png`, and
`artifacts/part1_diffusion_training_animation.json`. The animation uses fixed
display limits of `[-10, 10]` on both axes; raw trajectories are not clipped or
modified, and the raw extrema are recorded in the JSON file.

The final distribution evaluation writes
`evidence/part1_ddpm_distribution.png` and
`artifacts/part1_ddpm_distribution.json`. It compares 2,000 samples from the
update 25000 model with 2,000 independently sampled points from the exact
target mixture. Checkpoint animation and the quantitative distribution
evaluation complete the current Part 1 verification; Parts 2–5 remain pending.

The 2,000 generated samples produced these measured cluster statistics:

| target centre | population | measured centre | centre error | measured x spread | measured y spread |
| --- | ---: | --- | ---: | ---: | ---: |
| `(3, 0)` | `0.2350` | `(3.00198, 0.00063)` | `0.00207` | `0.30974` | `0.29658` |
| `(0, 3)` | `0.2625` | `(-0.01741, 2.97608)` | `0.02958` | `0.29270` | `0.31398` |

## Part 2: Deterministic Sampling with DDIM

DDIM provides a deterministic reverse sampler for the same noise schedule used
by DDPM. It uses one initial Gaussian state and no fresh reverse noise, so a
given model, initial state, and decreasing noise-level list produce the same
result. DDPM adds stochastic noise at intermediate reverse steps, while DDIM
uses the predicted clean point and the next cumulative noise level directly.

The implementation supports the complete 1000-level grid and sparse grids. It
also includes an exact conditional-mean noise predictor for the four-Gaussian
target. This predictor uses the known mixture parameters and posterior
component weights to isolate distribution and sampler behavior from neural
network prediction error.

Run the basic verification with:

```bash
uv run python scripts/verify_ddim.py
```

The verification output is saved to `artifacts/part2_ddim_verification.json`.
It checks full and sparse sampling, single and batch shapes, finite outputs,
repeatability, the `t=1`, middle, and `t=1000` exact predictor cases, and
`alpha_bar_0 = 1`.

### DDIM and DDPM comparison

The 2,000-sample comparison uses checkpoint `update_025000`, 1,000 reverse
steps, shared initial Gaussian states, and independent reverse noise for the
two DDPM runs. Run it with:

```bash
uv run python scripts/evaluate_ddim.py
```

The results are saved to `artifacts/part2_ddim_evaluation.json`. The figures
are `evidence/part2_ddim_ddpm_trajectories.png` and
`evidence/part2_ddim_ddpm_samples.png`. Both figures use the fixed coordinate
range `[-8, 8]` on both axes, and all generated points are retained in the
numerical evaluation.

The DDIM repeat maximum absolute difference was `0.0`, and its cluster
populations were `[0.2480, 0.2605, 0.2490, 0.2425]`. The corresponding
population tolerance of `0.25 ± 0.015` passed. The DDPM runs had same-cluster
fractions of `0.257` for paired samples and maximum absolute difference
`7.084068` between their outputs, demonstrating the intended stochastic
sampling behavior.

The measured within-cluster coordinate standard deviations were:

| sampler | cluster 1 | cluster 2 | cluster 3 | cluster 4 |
| --- | --- | --- | --- | --- |
| DDIM | `(0.2936, 0.3082)` | `(0.2984, 0.2875)` | `(0.3079, 0.3107)` | `(0.3062, 0.2868)` |
| DDPM run 1 | `(0.2968, 0.2925)` | `(0.2924, 0.2924)` | `(0.2929, 0.2977)` | `(0.2992, 0.2894)` |
| DDPM run 2 | `(0.3047, 0.3099)` | `(0.2969, 0.3191)` | `(0.3023, 0.2913)` | `(0.3139, 0.3127)` |

The course standard deviation interval is `[0.29, 0.32]`. The DDPM runs
passed this check. The DDIM result did not pass it because two coordinates
were below the lower bound: `0.2875` and `0.2868`. The measured results are
kept unchanged in the JSON artifact; no additional threshold was introduced
and no random seed was selected to hide the failed check. Therefore the
overall Part 2 comparison acceptance is recorded as failed despite the DDIM
determinism and population checks passing.

### DDIM spread diagnosis

A read-only review of `scripts/ddim.py`, `scripts/ddpm.py`,
`scripts/exact_noise.py`, `scripts/diffusion.py`, and
`scripts/evaluate_ddim.py` found no definite implementation error. The review
confirmed `alpha_bar_0 = 1`, the `t` to `t - 1` array indexing convention, the
`t - 1` time features, the complete `1000` through `0` grid, the final
deterministic update, and the absence of extra noise or clipping.

The diagnostic artifact `artifacts/part2_ddim_diagnosis.json` records a
separate 256-sample experiment with seed `7603`. It used the same initial
Gaussian states and the complete 1,000-step grid for the trained noise
predictor and the exact conditional-mean noise predictor. Their final outputs
had maximum absolute difference `1.968864`. The measured coordinate spreads
were:

| predictor | cluster 1 | cluster 2 | cluster 3 | cluster 4 |
| --- | --- | --- | --- | --- |
| Trained network | `(0.2494, 0.3107)` | `(0.3308, 0.3058)` | `(0.3247, 0.2599)` | `(0.3320, 0.2612)` |
| Exact conditional mean | `(0.2611, 0.3335)` | `(0.3149, 0.2998)` | `(0.3009, 0.2592)` | `(0.3199, 0.2799)` |

Both predictors produced finite values, but the diagnostic does not establish
a unique cause for the formal DDIM spread discrepancy. In particular, the
exact predictor also showed below-threshold spreads in this smaller sample.
The formal 2,000-sample evaluation remains unchanged and is the basis for the
reported course acceptance result; the 256-sample diagnostic is supporting
evidence only.
