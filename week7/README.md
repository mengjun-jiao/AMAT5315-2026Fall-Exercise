# Week 7: Diffusion and Flow Matching

## Project Overview

This project studies diffusion models, deterministic sampling, flow matching,
and image completion. Each part is implemented and verified separately
according to the Week 7 learning sheet.

## Environment Setup

The project uses an isolated `uv` environment with the same dependency
management style as Week 6. Run commands from this directory:

```bash
uv sync
uv run python -c "import jax; print(jax.devices())"
```

JAX is expected to run on the CPU by default. The device check should report a
`CpuDevice`. All future commands should use `uv run` so that the lock file and
environment are used consistently.

## Directory Structure

- `scripts/` contains source code, experiment entry points, validation scripts,
  and plotting scripts.
- `evidence/` contains reviewable figures generated by verified commands.
- `artifacts/` contains formal numerical results and experiment settings.
- `inputs/` contains downloaded datasets and model files and is excluded from
  version control.

## Part 1: Diffusion Models on a Gaussian Mixture

The target distribution and the 1000-step forward diffusion are implemented in
`scripts/diffusion.py`. The independent verification script samples the four
Gaussian components, checks the noise schedule, compares the direct and
stepwise formulas, and reports the `t=1000` statistics:

```bash
uv run python scripts/verify_forward_diffusion.py
```

The numerical settings and verification output are saved to
`artifacts/part1_forward_diffusion.json`. No reverse process or learned
predictor is included in this subtask.

The full forward trajectory of the same 2,000 target samples can be rendered

With seed 7201, the generated `t=1000` sample has mean and variance recorded

The time-conditioned noise predictor uses the fixed configuration in

## Part 2: Deterministic Sampling with DDIM

DDIM provides a deterministic reverse sampler for the same noise schedule used
by DDPM. It uses one initial Gaussian state and no fresh reverse noise, so a
given model, initial state, and decreasing noise-level list produce the same
result. DDPM adds stochastic noise at intermediate reverse steps, while DDIM
uses the predicted clean point and the next cumulative noise level directly.

The implementation supports the complete 1000-level grid and sparse grids. It
also includes an exact conditional-mean noise predictor for the four-Gaussian
target. This predictor uses the known mixture parameters and posterior
component weights to isolate distribution and sampler behavior from neural
network prediction error.

Run the basic verification with:

```bash
uv run python scripts/verify_ddim.py
```

The verification output is saved to `artifacts/part2_ddim_verification.json`.
It checks full and sparse sampling, single and batch shapes, finite outputs,
repeatability, the `t=1`, middle, and `t=1000` exact predictor cases, and
`alpha_bar_0 = 1`.

## Part 3: Flow Matching and the Cost of Fewer Steps

Flow Matching trains a velocity field along the linear path
`x_s = (1 - s) x_0 + s z`, where `x_0` comes from the four-component target
mixture and `z` is standard Gaussian noise. The training target is the constant
conditional velocity `u = z - x_0`. The model is a three-layer, 128-unit SiLU
MLP with 32 time features. Its time encoding uses 16 sine and 16 cosine
features with phase `1000 s 10000^(-j/16)`, concatenated with the two spatial
coordinates.

The prescribed configuration is stored in `flow.toml`: float32 arithmetic,
batch size 512, Adam, cosine learning-rate decay from `0.001` to `0.0`, seed
`2029`, and exactly 25,000 updates. Train the model with:

```bash
uv run python scripts/train_flow_matching.py
```

The full loss history and settings are saved to
`artifacts/part3_flow_training.json`. The final checkpoint is written to the
ignored local file `artifacts/checkpoints/flow_update_025000.npz`.

The exact marginal velocity uses the posterior weights of the four
interpolated Gaussian components. For component `k`, it uses variance
`(1 - s)^2 0.09 + s^2`, mean `(1 - s) mu_k`, and the analytic conditional
velocity specified by the learning sheet. It is implemented separately in
`scripts/exact_velocity.py`.

Verify the learned and exact fields with:

```bash
uv run python scripts/verify_flow_velocity.py
```

The verification uses a 41 by 41 grid over `[-4.5, 4.5]` in both coordinates
at `s = 0.1`, `0.5`, and `0.9`. It writes
`artifacts/part3_flow_velocity_verification.json` and
`evidence/part3_flow_velocity_fields.png`. The measured relative RMS errors
were:

| time | relative RMS error |
| ---: | ---: |
| `0.1` | `0.382280` |
| `0.5` | `0.317135` |
| `0.9` | `0.093909` |

The model dimensions, finite predictions at `s = 0`, `0.1`, `0.5`, `0.9`, and
`1`, the exact endpoint relation `v(x, 1) = x`, and the 25,000-entry training
history all passed. The course relative RMS criterion below `0.1` did not pass
at `s = 0.1` or `s = 0.5`; it passed at `s = 0.9`. A separate read-only check
on points sampled from the interpolating data path showed much smaller errors,
while the rectangular grid includes lower-density regions where the learned
field extrapolates. This observation does not establish a unique cause, and
the prescribed settings and acceptance threshold were left unchanged.

The full comparison of DDPM, DDIM, and Flow Matching sampling steps is
documented below.

### Sampling-step comparison

The full Part 3 sampler comparison uses the already trained checkpoints and
does not retrain either model. Run it with:

```bash
uv run python scripts/evaluate_part3_sampling.py
```

shared initial Gaussian batch, and one fixed exact reference batch from the
four-component target mixture. The experiment seed is `9317`. Flow Matching
uses Euler integration with `1`, `2`, `5`, `10`, `20`, `50`, and `100` steps.
DDIM and DDPM use the same step counts plus `1000` steps. Their integer grids
start at mathematical level `1000`, end at `0`, and contain exactly the
requested number of intervals. DDPM reverse-noise arrays use independent
deterministic subkeys for each step count.

The coarse DDPM sampler uses the cumulative-alpha jump formula and adds no
noise on the final transition. Its adjacent-level first transition agrees
with the validated single-step DDPM update to maximum absolute difference
`1.13e-6` in float32. No clipping is used.

## Part 4: The Same Predictor on Photographs

The local pretrained CIFAR model is stored under
`inputs/cifar-model/`. It consists of `config.json` and
`diffusion_pytorch_model.safetensors` for the inspected `UNet2DModel`
configuration. The loader in `scripts/load_cifar_checkpoint.py` reads the
Safetensors header directly and maps every local checkpoint tensor into a
float32 NumPy parameter dictionary without modifying the source file.

The JAX implementation in `scripts/cifar_unet.py` follows the local
configuration: 32 by 32 RGB input, block channels `[128, 256, 256, 256]`,
two ResNet layers per down block, the configured attention blocks, sinusoidal
positional time embedding, GroupNorm, time-conditioned ResNet blocks, skip
connections, and the output normalization and convolution. The canonical
model layout is NCHW, `(batch, channels, height, width)`. The forward
interface accepts mathematical noise levels `t` from `1` through `1000` and
passes `t - 1` to the checkpoint's zero-based timestep embedding.

Run the local forward-pass smoke test with:

```bash
uv run python scripts/smoke_test_cifar_unet.py
```

The results are saved to `artifacts/part4_cifar_unet_smoke_test.json`. The
test covers batch sizes `1` and `4` at `t = 1`, `500`, and `1000`. All six
outputs have shape `(batch, 3, 32, 32)`, contain finite values, and all 328
checkpoint tensors are mapped with no unused or missing tensors. This verifies
parameter loading and forward execution only; full 1,000-step CIFAR DDPM
image generation has not been run yet.
